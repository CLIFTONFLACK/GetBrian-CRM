## Bugs to fix (ordered)

1. **Reset to default is a no-op.** admin-panel.tsx Deep Dive Textarea is uncontrolled
   (`defaultValue`), so Reset changes React state but the DOM value is what posts.
   Make it `value={promptValue}`. (File currently edited by the Didit session.)
2. **Primary contact never pre-ticked.** send-deal-modal accepts `defaultContactIds`
   but none of the five callers pass it; `getPrimaryContactForCompany` has no callers.
3. **Unique-violation 500s when re-parenting a primary contact** (contacts.ts:145 and
   companies.ts:222 via linkContactToCompany). Clear is_primary when company_id changes.
4. **Importer has no admin check** (import-data.ts requireCaller). Any member can bulk
   UPDATE the tenant. Use requireAgencyAdmin.
5. **Client-supplied file_path trusted** in requirement-documents.ts:55 (and the older
   disposal-documents.ts). Validate host/path prefix before insert; the signed proxy
   302s to it and delete() runs with the server Blob token.
6. **Deleting a requirement orphans its landlord-pack blobs** (no del() as in
   deleteDisposal).
7. **Importer rejects external_ref update rows** that omit company/contact columns:
   link rule runs before the existing-row lookup (import-data.ts:429).
8. **Deep Dive Q&A ordering** has no tiebreaker; question and answer share created_at.
9. **askDeepDive persists outside try/catch**: paid answer lost on a DB hiccup.
10. Requirement company_id/contact_id not checked against caller's agency
    (requirements.ts:60). Existence oracle only.
11. No recipient cap on shared To: (Resend rejects >50); bounce stamps all recipients;
    stale copy "to one contact" in match-opportunities.tsx:115.
12. Non-UUID ids in requirement-docs/upload routes surface as 500 not 404.
13. Saving the default prompt stores it as an override rather than NULL.

### Deep Dive run: fails from the automated browser, unexplained

Four clicks on Run Deep Dive for "Alexander Pashby T/A The Beefsteaks" (three by the
reviewer, one by me) each left the tab busy for 60–100 s, then showed "No Deep Dive yet"
with no error. The database has no row for any of them, not even a `failed` row, which the
server writes on any exception. So the request never executed server-side.

Evidence the server path is healthy:
- deep_dive_reports holds one complete report (Bangers London, 06:54 today, this build)
  plus one saved Q&A exchange, made from a normal browser.
- The exact Pashby prompt sent from this machine with the stored key returned 200 in
  3.2 s (5.9 KB report, cost $0.0066). A second probe with a broken prompt also returned
  in 2.8 s ($0.005). Total spent on probes: about $0.012.

Both failing runs used the Claude-in-Chrome automation extension, which was also
timing out on ordinary page reads in the same tab. Most likely a tooling artefact rather
than an app fault, but unconfirmed. One click from Brian on that company in a normal
browser settles it. Vercel function logs for this project sit under the clifton-ai-team
scope, which this machine's Vercel login (slapharma) cannot read.
